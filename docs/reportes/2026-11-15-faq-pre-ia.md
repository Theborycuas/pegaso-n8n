# FAQ pre-IA desde historial real (sin Redis)

**Estado:** implementado en local, sin publicar en n8n ni commit.

## Resultado

Se muestrearon **46 turnos conversacionales reales** (ejecuciones exitosas del workflow con duración ≥ 1,5 s, nov-2026) y se bajaron las preguntas fijas más repetidas a una **tabla FAQ pre-IA** en `Preparar contexto IA` (V4.23). Esas coincidencias saltan el cerebro (`requiere_cerebro_comercial = false`). El resolver (V3.34) refuerza ubicación cuando el cliente dice solo “dirección”.

No se tocó Redis. La “tabla” vive en código (`TABLA_FAQ_PRE_IA`); una tabla Postgres opcional queda documentada al final para más adelante.

## Tabla Postgres (opcional, después)

Sin Redis. Si más adelante se quiere editar respuestas sin republicar:

```sql
CREATE TABLE IF NOT EXISTS pegaso.faq_respuestas (
  id text PRIMARY KEY,
  patron text NOT NULL,
  accion varchar(40) NOT NULL,
  intencion varchar(40) NOT NULL,
  respuesta text NOT NULL,
  max_len int NULL,
  activo bool DEFAULT true,
  actualizado_at timestamptz DEFAULT now()
);
```

Hoy la fuente de verdad es el código; `configuracion_bot` ya cubre imágenes (material, metodología, datos de pago).

## Riesgos

- Un mensaje corto con «IVA» o «envío» junto a otra pregunta puede matchear FAQ y no cotizar: hay `maxLen` y se excluyen turnos con medidas/`NxN`.
- IVA pre-IA asume etiquetas adhesivas (lo más frecuente en leads de anuncio); líneas de catálogo sin IVA siguen cubiertas por el texto del catálogo y por 12.11b si el turno llega al resolver con otra acción.
